Interviewer question - AI-enabled version

Interviewer
This repository contains a partially implemented Snake Game engine and tests. Extend it so the snake grows only after every Nth food item, where N is configuration. Preserve the existing nextMove(direction) API, follow the repository's boundary policy, end the game on invalid collision, and keep movement efficient. Use the AI assistant, but drive the design and testing yourself.

What should I think about first?

Think
  1. Clarify the growth trigger. Nth food and Nth move are different requirements. The practice version uses Nth food.
  2. Clarify board boundaries. Wall collision and wraparound produce different position logic and tests.
  3. Model the snake as ordered state plus membership state. A deque/array tracks head-to-tail order; a set provides O(1) collision checks.
  4. Handle the old-tail exception correctly. Moving into the current tail is legal when the tail moves away on a non-growth step.
  5. Keep food deterministic in tests. Inject a provider or sequence instead of relying on random generation.
I will confirm whether growth is based on food count or move count, whether boundaries wrap or end the game, and how food is supplied. Then I will inspect the current engine and tests, add the smallest failing test for the Nth-food rule, implement the minimum state transition, and add the tail-collision and boundary edge cases before reviewing the design.

One move as an explicit state machine
flowchart LR
  D[Direction] --> P[Compute candidate head]
  P --> B{Boundary policy}
  B -->|invalid| G[Mark game over]
  B -->|valid position| F{Candidate is food?}
  F --> C[Compute whether this food triggers growth]
  C --> T{Will tail move?}

  T -->|no| K[Keep tail]
  R --> X{Candidate occupied?}

  X -->|yes| G
  X -->|no| H[Add candidate as new head]
  H --> E[Advance food if consumed]
  E --> O[Return move result]
Collision is checked after removing the tail on a non-growth move, otherwise entering the old tail cell is incorrectly rejected.

Acceptance criteria

  • The existing nextMove(direction) contract and existing movement behavior remain compatible.
  • Eating food increments the food counter; length grows only when the new count is divisible by growthEvery.
  • On a non-growth move, the tail is removed before occupancy collision is evaluated.
  • Self-collision ends the game and does not partially mutate the body.
  • Boundary behavior follows explicit repository configuration: wrap or wall.
  • Food progression is deterministic in tests and never places food on an occupied cell.
  • Each move is O(1) except any explicitly separate food-generation search.
  • Focused and regression tests pass; no unrelated rendering/UI rewrite is included.

Representative TypeScript design

export type Direction = 'UP' | 'DOWN' | 'LEFT' | 'RIGHT';
export type BoundaryMode = 'WRAP' | 'WALL';

export interface Position {
  readonly row: number;
  readonly col: number;
}

export interface FoodProvider {
  current(): Position | null;
  consume(): void;
}

export interface MoveResult {
  readonly gameOver: boolean;
  readonly ateFood: boolean;
  readonly grew: boolean;
  readonly head: Position;
  readonly length: number;
}

const keyOf = ({ row, col }: Position): string => `${row}:${col}`;

export class SnakeGame {
  private readonly body: Position[];
  private readonly occupied: Set<string>;
  private foodsEaten = 0;
  private gameOver = false;

  constructor(
    private readonly boardSize: number,
    initialBody: Position[], // tail -> head
    private readonly growthEvery: number,
    private readonly boundaryMode: BoundaryMode,
    private readonly food: FoodProvider,
  ) {
    if (boardSize <= 0 || growthEvery <= 0 || initialBody.length === 0) {
      throw new Error('Invalid game configuration');
    }

    this.body = [...initialBody];
    this.occupied = new Set(initialBody.map(keyOf));

    if (this.occupied.size !== initialBody.length) {
      throw new Error('Initial snake contains duplicate positions');
    }
  }

  nextMove(direction: Direction): MoveResult {
    if (this.gameOver) {
      return this.result(false, false);
    }

    const candidate = this.moveFrom(this.head(), direction);
    const bounded = this.applyBoundary(candidate);
    if (bounded === null) {
      this.gameOver = true;
      return this.result(false, false);
    }

    const currentFood = this.food.current();
    const ateFood = currentFood !== null && keyOf(currentFood) === keyOf(bounded);
    const nextFoodCount = this.foodsEaten + (ateFood ? 1 : 0);
    const grew = ateFood && nextFoodCount % this.growthEvery === 0;

    // On a normal move the tail leaves first. This makes moving into the
    // old tail position legal when the snake is not growing.
    if (!grew) {
      const tail = this.body.shift();
      if (tail) this.occupied.delete(keyOf(tail));
    }

    if (this.occupied.has(keyOf(bounded))) {
      this.gameOver = true;
      return this.result(ateFood, false);
    }

    this.body.push(bounded);
    this.occupied.add(keyOf(bounded));

    if (ateFood) {
      this.foodsEaten = nextFoodCount;
      this.food.consume();
    }

    return this.result(ateFood, grew);
  }

  private head(): Position {
    return this.body[this.body.length - 1];
  }

  private moveFrom(position: Position, direction: Direction): Position {
    const delta = {
      UP: [-1, 0], DOWN: [1, 0], LEFT: [0, -1], RIGHT: [0, 1],
    } as const;
    const [rowDelta, colDelta] = delta[direction];
    return { row: position.row + rowDelta, col: position.col + colDelta };
  }

  private applyBoundary(position: Position): Position | null {
    const inside = position.row >= 0 && position.row < this.boardSize
      && position.col >= 0 && position.col < this.boardSize;
    if (inside) return position;
    if (this.boundaryMode === 'WALL') return null;
    return {
      row: (position.row + this.boardSize) % this.boardSize,
      col: (position.col + this.boardSize) % this.boardSize,
    };
  }

  private result(ateFood: boolean, grew: boolean): MoveResult {
    return {
      gameOver: this.gameOver,
      ateFood,
      grew,
      head: this.head(),
      length: this.body.length,
    };
  }
}
Mutation safety detail

The sample removes the tail before checking collision. If collision then occurs, the state is partially changed. A production-quality implementation should either pre-compute whether the candidate is legal using the old-tail exception, or stage the mutation and commit only after validation. This is exactly the kind of issue you should notice in the diff rather than blindly accept AI-generated code.

Safer collision decision

const tail = this.body[0];
const mayEnterOldTail = !grew && keyOf(tail) === keyOf(bounded);
const collides = this.occupied.has(keyOf(bounded)) && !mayEnterOldTail;

if (collides) {
  this.gameOver = true;
  return this.result(ateFood, false);
}

if (!grew) {
  const removed = this.body.shift();
  if (removed) this.occupied.delete(keyOf(removed));
}

this.body.push(bounded);
this.occupied.add(keyOf(bounded));

Use this staged form in the final implementation so an invalid move does not corrupt the body.

describe('SnakeGame Nth-food growth', () => {

Likely P40 follow-ups

Why use both a deque/array and a set?

The ordered collection identifies head and tail and supports O(1) end updates. The set provides O(1) occupancy checks. The invariant is that both contain exactly the same positions; tests and encapsulation protect that duplication.

How would you generate random food efficiently?

For a small board, sample cells until one is free. At high occupancy that degrades. A free-cell set plus index mapping supports random O(1) selection/update but adds state complexity. Keep food generation behind an interface so the engine is testable.

What if boundary behavior changes at runtime?

Represent boundary handling as a policy, but only if the requirement needs runtime switching. Otherwise an immutable constructor configuration is simpler and safer.

How would you support pause, replay or undo?

Record accepted commands and deterministic food sequence, or emit immutable move events. Replay from an initial seed/state. Undo requires snapshots or reversible events and is a separate product requirement.

How would React use this engine?

Keep the engine UI-independent. A hook/controller owns the timer and dispatches directions, then maps immutable move results/body snapshots to rendering. Do not let DOM state become the game source of truth.

What if the snake fills the board?

The food provider must detect no free cell and return a win/completed state instead of looping forever. Clarify whether full-board completion is required.

How would you make it multiplayer?

That changes the consistency model: one authoritative server tick, ordered commands, simultaneous collision resolution and client prediction/reconciliation. Do not force multiplayer abstractions into the single-player exercise.

Common mistakes

  • Assuming wraparound or wall collision without asking.
  • Confusing every Nth food with every Nth move.
  • Checking occupancy before accounting for the old tail leaving.
  • Mutating the body before proving the candidate move is valid.
  • Using random food directly in unit tests.
  • Scanning the whole snake on each move when O(1) membership is expected.
  • Letting AI rename the public API or rewrite the UI unnecessarily.

I preserved the existing nextMove API and added the Nth-food rule through a focused TDD sequence. The engine keeps ordered body state plus an occupancy set so movement and collision remain O(1).
