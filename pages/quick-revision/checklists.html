Interview checklists

Use the relevant section shortly before each round. These are execution controls, not another syllabus.

Universal setup

  • Calendar time, timezone, interviewer name and round title confirmed.
  • Quiet location, stable internet, charger, water, audio and camera checked.
  • Resume and role description open, with confidential details removed from notes.
  • Two questions for the interviewer prepared.
  • One-sentence introduction and one-sentence closing practised.
  • No new material in the final hour.

AI-Enabled Code Design · before the round

  • Can state Clarify → Baseline → Trace → Alternatives → RED → GREEN → Refactor → Regression → Diff → Explain.
  • Know Maven/Gradle/npm test commands, debugger basics and how to inspect Git diff.
  • Have bounded discovery, RED, GREEN, regression and review prompts ready.
  • Will run a baseline and make the smallest behavior test fail before production changes.
  • P40 drill order: Agent Rating, Middleware Router, API Rate Limiter, then Snake Game.
  • Will keep AI prompts and decisions visible to the interviewer.
  • Will not accept code I cannot explain.

Final diff review

  • Unrelated formatting or refactoring?
  • New dependency or public contract change?
  • Other mutation paths bypassing the rule?
  • Null, boundary, malformed and security cases?
  • Tests that pass for the wrong reason?
  • Debug logs, secrets, dead code or weak error handling?

Full-Stack System Design · before the round

  • Start with users, top workflows, NFRs and out-of-scope.
  • Define entities and dominant reads/writes before choosing storage.
  • Connect frontend behavior to backend guarantees.
  • Add cache, queue, search and real-time components only when justified.
  • Cover tenancy, permissions and customer-visible failures.
  • Reserve the last 7 minutes for concurrency, recovery, observability and trade-offs.

Design pressure test

  • What happens on retry?
  • What happens on reconnect?
  • What happens when permission is revoked?
  • What is authoritative versus a projection?
  • Where can duplicates or out-of-order events occur?
  • What is the first bottleneck or hot key?
  • How is a schema/API/event change rolled out safely?

Management Interview · before the round

  • Master stories selected: pricing fallback, Spark consolidation, migration/integration, failure, conflict, triage, mentoring, Promo UI and Wally backup.
  • Each story starts with business/customer need, not technology.
  • Personal work is separated from team work.
  • At least one verified result and one rejected alternative are ready.
  • One real conflict, feedback, mentoring and failure story are prepared.
  • Why Atlassian, why full stack, why now and two-to-three-year direction are specific.

Management answer audit

  • Did I answer the question before giving background?
  • Could the interviewer identify what I personally decided?
  • Did I make scope and cross-team influence visible?
  • Is the other person's perspective represented fairly?
  • Did I show business/customer/operational impact?
  • Did I name what I would do differently?
  • Am I leaving room for follow-ups rather than speaking for six minutes?

Values Interview · before the round

  • One primary and one backup story for each value.
  • Open: production disagreement or backend-visibility feedback; directness plus care.
  • Heart + balance: pricing fallback/aggregation or staged migration; real options and reversible risk.
  • Customer: pricing correctness, Promo UI or Wally streaming; name the user-visible consequence.
  • Team: rollout triage or mentoring; who benefited and what you gave up.
  • Change: Spark consolidation, Promo UI or changing your own communication habits; show durability.
  • Each core answer fits 90 seconds.

Values answer audit

  • Did I show a real tension rather than an easy success?
  • Did I describe observable behavior—what I said, asked or changed?
  • Did I avoid value slogans and excessive architecture?
  • Did I acknowledge my own contribution to the problem?
  • Did I use only verified facts and metrics?
  • Did I explain the permanent lesson?

Five minutes before joining

  1. Close courses, chat windows and unrelated browser tabs.
  2. Open only the round page, resume, role description and one blank note page.
  3. Say the opening out loud once.
  4. Take two slow breaths and decide the first action, not the final outcome.
  5. Join early and confirm audio.

After every round

  • Write the exact questions and follow-ups while fresh.
  • Record assumptions, strong moments, weak moments and interviewer cues.
  • Save new candidate-specific information for the next round.
  • Send a concise thank-you through the appropriate channel when customary.
  • Then stop replaying the round and prepare the next stage.
